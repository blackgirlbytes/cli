## New Findings

### Critical (Must Fix)

- **[phase_postcommit_test.go:2522-2528] `TestPostCommit_WarnStaleEndedSessions_AfterProcessing` mutates `os.Stderr` -- unsafe for concurrent tests.** The test replaces `os.Stderr` with an `os.Pipe()` and restores it in a deferred function. This is process-global state. If `PostCommit` writes the warning via the production `warnStaleEndedSessions` path (which hardcodes `os.Stderr`), the capture works only because `warnStaleEndedSessions` reads the `os.Stderr` variable at call time rather than caching it at init. This is correct today but would silently break if `warnStaleEndedSessions` were refactored to capture stderr at initialization. **Suggested fix:** Since `warnStaleEndedSessionsTo` already accepts an `io.Writer`, consider making the writer injectable at the `PostCommit` level (e.g., via a package-level `var stderrWriter io.Writer = os.Stderr` that tests can swap), or at minimum add a comment documenting that the `os.Stderr` swap is intentional and depends on the variable being read at call time.

### Important (Should Fix)

- **[manual_commit_session.go:112-115] `isWarnableStaleEndedSession` performs a shadow branch lookup that is redundant with `listAllSessionStates` -- add a clarifying comment.** The `sessions` slice comes from `findSessionsForWorktree` -> `listAllSessionStates`, which already checks shadow branch existence (line 92) and removes orphaned sessions. However, the re-check in `isWarnableStaleEndedSession` is *intentionally* not redundant: PostCommit deletes shadow branches between the list-load and the warning check, so the re-check detects freshly-deleted branches. **This is correct but needs a comment** explaining the intent. Without it, a future reader will see two identical `repo.Reference()` calls and may remove the "duplicate."

- **[manual_commit_hooks.go:934] Warning counts stale sessions only in the current worktree.** The `sessions` variable is scoped to `findSessionsForWorktree`, so stale ENDED sessions from other worktrees are invisible. If a user has 10 stale sessions spread across 3 worktrees (2+3+5), no single worktree hits the threshold of 3. This is arguably correct since PostCommit only processes worktree-local sessions, but the warning message ("slowing down commits") does not communicate the worktree scope. **Suggested fix:** Either count globally via `listAllSessionStates`, or adjust the message to include "in this worktree."

- **[phase_postcommit_test.go:2506] Map iteration order makes `filesToCommit` non-deterministic.** The test iterates over `sessionFiles` (a `map[string]string`) to build the `filesToCommit` slice. Go map iteration is randomized, so the commit tree structure differs across runs. While correctness is unaffected (all 3 files are included), this makes test failures harder to reproduce. **Suggested fix:** Use a slice of structs or sort `filesToCommit` before passing to `commitFilesWithTrailer`.

### Suggestions (Consider)

- **[manual_commit_hooks.go:762-766] Warning message references `entire doctor` but the plan document says `entire clean --force`.** The commit message says "align stale ended-session warning with doctor," so this appears intentional. The plan document (lines 7, 295, 333) consistently references `entire clean --force`. Confirm which command is correct. If `entire doctor` is the new preferred command, the plan document is stale (not blocking, but worth noting).

- **[manual_commit_hooks.go:759] Defensive `os.MkdirAll` for `entire-sessions/` directory.** If `entire-sessions/` does not exist, the warning's premise (stale sessions exist) is contradicted -- sessions are loaded from this directory. The `MkdirAll` cannot hurt but is logically unnecessary. Consider removing it and letting `WriteFile` fail silently.

- **[manual_commit_session.go:108] `StepCount <= 0` vs `StepCount == 0`.** A negative `StepCount` should be impossible. Using `<= 0` is fine defensively, but `== 0` would be more self-documenting about the intent (no checkpoints to condense).

- **[phase_postcommit_test.go:2433] `TestCountWarnableStaleEndedSessions` lacks the `t.Chdir` warning comment.** The test uses `t.Chdir(dir)` and correctly omits `t.Parallel()`, but unlike `TestWarnStaleEndedSessions_RateLimit` (line 2542), it does not have the `// Uses t.Chdir -- do NOT add t.Parallel().` comment. Add it for consistency.

- `isWarnableStaleEndedSession` cleanly encodes all four conditions, and `TestCountWarnableStaleEndedSessions` covers each exclusion criterion individually (no shadow branch, zero steps, fully condensed, wrong phase). Thorough coverage.
