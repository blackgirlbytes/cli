Found 2 issues:

1. **`entire review` never discovers external agents before using the registry**  
   `newReviewCmdWithDeps` calls `runReview` directly (`cmd/entire/cli/review.go:463-469`), and `runReview` immediately relies on `GetAgentsWithHooksInstalled` / `agent.Get` (`review.go:541-608`, `config.go:86-97`). Unlike `review attach`, this path never calls `external.DiscoverAndRegister(...)` (`review.go:507-513`). As a result, a review config that targets an external agent can’t be used: the agent won’t be present in the registry, won’t appear as “hooks installed”, and `entire review` will fail even though `entire attach`/hook paths work. This breaks the documented manual-settings/external-agent review flow.

2. **The review picker says saved skills are pre-checked, but it never actually preselects them**  
   `runReviewConfigPicker` advertises “Previously-saved skills are pre-checked” (`cmd/entire/cli/review.go:307-327`), but the implementation only restores `Prompt` (`review.go:353-359`). `builtinPicks` / `discoveredPicks` start empty, and `buildReviewPickerFields` creates every `huh.Option` without `.Selected(true)` (`review.go:1120-1144`). So opening `entire review --edit` on an existing config and accepting defaults will clear that agent’s saved skills instead of preserving them. That’s a destructive regression in the edit flow.
