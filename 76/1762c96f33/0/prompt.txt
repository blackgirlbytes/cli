Plan: Remove env-var TTY gating — pure /dev/tty detection for huh forms

 Context

 The Entire CLI uses charmbracelet/huh for interactive terminal forms across ~39 callsites. Currently, two env vars control TTY behavior:

 - ENTIRE_TEST_TTY (100+ references): overrides /dev/tty detection in tests and e2e
 - ACCESSIBLE (5 references): toggles huh's accessible (plain-text) mode

 These proxy for one question: "is there a TTY?" The goal is to replace env-var gating with pure runtime TTY detection — no TTY means no form,
 automatically. A Go function-variable test seam replaces the env vars for unit tests.

 Additionally, strategy/manual_commit_hooks.go has a separate hasTTY() with agent-detection logic (GEMINI_CLI, COPILOT_CLI, PI_CODING_AGENT,
 GIT_TERMINAL_PROMPT). This logic must be consolidated into the shared interactive package.

 Step 1: Rewrite interactive/interactive.go — single source of TTY truth

 File: cmd/entire/cli/interactive/interactive.go

 Replace the current implementation with:

 package interactive

 import "os"

 // canPrompt is the TTY detection function. Swappable in tests via OverrideForTest.
 var canPrompt = checkCanPrompt

 // CanPromptInteractively reports whether interactive prompts can be shown.
 // Returns false when there is no controlling terminal, or when running
 // inside an AI agent subprocess that inherits the user's TTY but cannot
 // respond to prompts.
 func CanPromptInteractively() bool {
        return canPrompt()
 }

 func checkCanPrompt() bool {
        // Agent subprocesses may inherit the user's TTY but cannot respond
        // to interactive prompts. Detect known agents and bail out.
        if isAgentSubprocess() {
                return false
        }

        tty, err := os.OpenFile("/dev/tty", os.O_RDWR, 0)
        if err != nil {
                return false
        }
        _ = tty.Close()
        return true
 }

 // isAgentSubprocess returns true when the process is a subprocess of a known
 // AI coding agent. These agents may pass through the user's TTY but cannot
 // respond to interactive prompts on the user's behalf.
 func isAgentSubprocess() bool {
        if os.Getenv("GEMINI_CLI") != "" {
                return true
        }
        if os.Getenv("COPILOT_CLI") != "" {
                return true
        }
        if os.Getenv("PI_CODING_AGENT") != "" {
                return true
        }
        if os.Getenv("GIT_TERMINAL_PROMPT") == "0" {
                return true
        }
        return false
 }

 // OverrideForTest replaces TTY detection for the duration of a test.
 // Returns a restore function that must be deferred.
 //
 //     restore := interactive.OverrideForTest(func() bool { return false })
 //     defer restore()
 func OverrideForTest(fn func() bool) func() {
        old := canPrompt
        canPrompt = fn
        return func() { canPrompt = old }
 }

 Key points:
 - Agent-detection logic moves here FROM strategy/manual_commit_hooks.go:hasTTY()
 - ENTIRE_TEST_TTY env var is gone — replaced by OverrideForTest()
 - OverrideForTest is exported so all packages can use it

 Step 3: Add Form wrapper type to utils.go

 File: cmd/entire/cli/utils.go

 Replace NewAccessibleForm and IsAccessibleMode with:

 // Form wraps huh.Form with automatic TTY detection.
 // When no controlling terminal is available, Run() returns nil
 // and all field values remain at their defaults.
 type Form struct {
        inner *huh.Form
 }

 // NewForm creates a new Form with the Entire theme applied.
 // The form will only run if a TTY is available.
 func NewForm(groups ...*huh.Group) *Form {
        return &Form{
                inner: huh.NewForm(groups...).WithTheme(entireTheme()),
        }
 }

 // Run executes the form if a TTY is available. Returns nil immediately
 // when no terminal is present (CI, agent subprocesses, piped input).
 func (f *Form) Run() error {
        if !interactive.CanPromptInteractively() {
                return nil
        }
        return f.inner.Run()
 }

 Delete:
 - IsAccessibleMode() function
 - NewAccessibleForm() function

 Keep unchanged:
 - entireTheme()
 - handleFormCancellation()

 Step 10: Migrate integration tests

 File: cmd/entire/cli/integration_test/testenv.go

 10a. cliEnv() (line 140)

 Remove "ENTIRE_TEST_TTY=0" from the environment list. Without a PTY, the subprocess has no /dev/tty, so CanPromptInteractively() returns false
 naturally.

 10b. gitCommitWithShadowHooks() (lines 1118-1126)

 Currently toggles ENTIRE_TEST_TTY=1 vs ENTIRE_TEST_TTY=0 based on simulateTTY.

 - When simulateTTY=true: the test should use pty.Start() to give the child a real TTY. If the test already uses PTY, just remove the env var — the
 real TTY is enough.

 If some tests set simulateTTY=true but DON'T use a PTY (relying solely on the env var to fake TTY presence), those tests need adjustment. They should
 either:
 - Actually use a PTY, or
 - Accept that the non-interactive path runs and verify that behavior instead

 10c. RunCommandInteractive() in integration_test/interactive.go (line 29)

 Remove "ACCESSIBLE=1" from the env. The test already uses pty.Start() which gives a real TTY. However, this means huh will render full TUI output
 instead of plain text. Two options:
 - Recommended: Keep "ACCESSIBLE=1" ONLY in this integration test helper. It's not gating TTY detection — it's controlling huh's output format so
 WaitForPromptAndRespond can parse plain text. This is a legitimate use of the accessibility feature.
 - Alternative: Rewrite WaitForPromptAndRespond to strip ANSI sequences. Higher effort, fragile.
