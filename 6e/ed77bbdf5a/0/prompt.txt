# Plan: Real Push Performance Test for `entire/checkpoints/v1`

## Context

We're working on JSONL compression (zstd) for session transcripts. Before integrating compression, we need baseline measurements of how long it takes to push the `entire/checkpoints/v1` branch to GitHub with realistic data. This will let us compare before/after compression to quantify the real-world push time improvement.

The existing benchmarks (`BenchmarkSimulatedPushPayload`) only estimate payload sizes locally — they never actually push to a remote. We need a test that pushes to a real GitHub repo and measures wall-clock time.

## Approach

Create a Go test file with a `pushperf` build tag that:
1. Creates a temporary private GitHub repo via `gh`
2. Sets up a local repo with realistic checkpoint data on `entire/checkpoints/v1`
3. Pushes to GitHub and measures wall-clock time
4. Reports structured results (duration, data size, throughput)
5. Cleans up the GitHub repo

### New file: `cmd/entire/cli/checkpoint/push_perf_test.go`

**Build tag:** `//go:build pushperf` — never runs in CI, only manually.

**Test function:** `TestPushPerformance(t *testing.T)`

**Setup per scenario:**
1. `t.TempDir()` → `git.PlainInit()` → initial commit (minimal, just a README)
2. `checkpoint.NewGitStore(repo)` for writing checkpoints
3. `gh repo create evisdrenova/entire-push-perf-test --private` (once, reused across subtests)
4. `git remote add origin <url>`

**Test matrix (subtests):**

| Scenario | Checkpoints | Transcript Size | What it measures |
|---|---|---|---|
| `FirstPush/10cp_100KB` | 10 | 100KB each | Small project baseline |
| `FirstPush/50cp_100KB` | 50 | 100KB each | Medium project |
| `FirstPush/50cp_500KB` | 50 | 500KB each | Medium project, longer sessions |
| `FirstPush/100cp_500KB` | 100 | 500KB each | Active project |
| `FirstPush/200cp_500KB` | 200 | 500KB each | Heavy usage |
| `Incremental/50cp_base_1new` | 50 existing + 1 new | 500KB | Typical incremental push |
| `Incremental/200cp_base_1new` | 200 existing + 1 new | 500KB | Heavy incremental push |

**Per scenario:**
1. Seed checkpoints via `store.WriteCommitted()` in a loop with `generateBenchJSONL()` (reuse from worktree's compression bench)
2. Run `git gc` to pack objects (realistic — git repos are usually packed)
3. Measure local repo size: `git count-objects -vH` and `du -sh .git/`
4. Time the push: `git push --no-verify origin entire/checkpoints/v1`
5. For incremental: push baseline first, add 1 checkpoint, time second push
6. Log results: checkpoint count, total data size, compressed pack size, push duration, effective MB/s

**Cleanup:**
- `t.Cleanup()` deletes the GitHub repo via `gh repo delete --yes`

### Helper functions in the same file

- `createTempGitHubRepo(t) string` — creates repo, returns URL
- `deleteTempGitHubRepo(t, name)` — deletes repo
- `seedCheckpoints(t, store, count, transcriptSize)` — writes N checkpoints with given transcript size
- `generateBenchJSONL(targetSize int) []byte` — generates realistic JSONL (copy from worktree's `compression_bench_test.go`)
- `measureRepoSize(t, dir) (looseKB, packKB int64)` — runs `git count-objects -v`
- `timePush(t, dir, remote, branch) time.Duration` — times `git push`

### Key reuse

- `checkpoint.NewGitStore` / `store.WriteCommitted()` — existing checkpoint writing
- `id.Generate()` — existing checkpoint ID generation
- JSONL generation pattern from worktree's `compression_bench_test.go:generateBenchJSONL`

### Output format

```
=== FirstPush/50cp_500KB ===
  Checkpoints:    50
  Transcript:     500KB each
  Total raw:      28.5 MB
  Pack size:      4.2 MB
  Push duration:  3.4s
  Throughput:     1.2 MB/s
```

## How to run

```bash
go test -v -run TestPushPerformance -tags pushperf -timeout 10m ./cmd/entire/cli/checkpoint/
```
