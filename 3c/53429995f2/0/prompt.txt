Reported regression:
Running `entire migrate --checkpoints v2` in the peregrine repo migrated 13 checkpoints but created an archived v2 full-generation ref:

  refs/entire/checkpoints/v2/full/0000000000001
  refs/entire/checkpoints/v2/full/current

This is unexpected because the v2 generation rotation threshold is 100 checkpoints, and 13 is below that threshold. Expected behavior: under-threshold migrated raw transcripts should not create a numbered archived `/full/<n>` generation merely because migration completed.
</context>

<root_cause_summary>
The migrate path has its own raw-transcript packing flow that differs from normal v2 writes.

Relevant current source:
- `cmd/entire/cli/migrate.go`
  - `migrateCheckpointsV2` creates a `generationPacker` and queues migrated raw transcripts with `packer.add(...)`.
  - `migrateOneCheckpoint` writes v2 `/main` data using `mainOpts.Transcript = redact.AlreadyRedacted(nil)`, so raw transcripts are intentionally not written by `WriteCommittedWithSessionIndex` during migration.
  - `generationPacker.add` flushes only when `len(p.pending) >= p.batchSize`.
  - `generationPacker.finalize` unconditionally calls `p.flush(ctx)`, so the final partial batch is archived into `refs/entire/checkpoints/v2/full/<n>` even when it contains fewer than `DefaultMaxCheckpointsPerGeneration` checkpoints.

Normal v2 writes behave differently:
- `cmd/entire/cli/checkpoint/v2_committed.go`
  - `rotateCurrentIfNeeded` counts checkpoints in `/full/current` and returns early when `checkpointCount < s.maxCheckpoints()`.
- `cmd/entire/cli/checkpoint/v2_generation.go`
  - `DefaultMaxCheckpointsPerGeneration = 100`.

So the regression is: migration treats the rotation threshold as a packing batch size and archives the final partial batch at process finalization, while normal writes only archive after the threshold is reached.
</root_cause_summary>
