# Checkpoint Viewer Prototype

## Context

The Entire CLI tracks AI agent sessions by creating checkpoints on the `entire/checkpoints/v1` git branch and adding `Entire-Checkpoint` trailers to user commits. There's currently no easy way to visually monitor these checkpoints in real time while developing. This prototype provides a lightweight web dashboard that auto-refreshes, showing committed checkpoints and active sessions at a glance.

## Approach

A **single Go binary** (zero external dependencies, stdlib only) that:
1. Shells out to `git` commands to read checkpoint data
2. Reads active session files from `.git/entire-sessions/`
3. Serves a single embedded HTML page with a polling JSON API (every 3s)
4. Dark theme, timeline view

## Files

```
prototype/
  main.go       # HTTP server + git data reading + embedded HTML
  index.html    # Single-page frontend (inline CSS + JS)
  go.mod        # module declaration only, no external deps
```

## API Endpoints

### `GET /api/checkpoints`
Lists commits on the current branch that have `Entire-Checkpoint` trailers, enriched with metadata from `entire/checkpoints/v1`.

**Git commands used:**
```bash
# Get commits with checkpoint trailers (null-separated fields)
git log --format='%H%x00%s%x00%aI%x00%(trailers:key=Entire-Checkpoint,valueonly)' -50

# For each checkpoint ID, read root + session metadata
git show "entire/checkpoints/v1:<id[:2]>/<id[2:]>/metadata.json"
git show "entire/checkpoints/v1:<id[:2]>/<id[2:]>/0/metadata.json"
```

**Response shape:**
```json
[{
  "hash": "c780808...",
  "short_hash": "c780808",
  "subject": "Use signal.NotifyContext()...",
  "date": "2026-02-19T13:29:50-08:00",
  "checkpoint_id": "4d7e19fbfd1e",
  "metadata": {
    "strategy": "manual-commit",
    "checkpoints_count": 2,
    "files_touched": ["cmd/entire/main.go"],
    "agent": "Claude Code",
    "session_id": "be55d75e-...",
    "created_at": "2026-02-19T21:29:54Z",
    "token_usage": { "input_tokens": 31, "output_tokens": 1413, "api_call_count": 21, ... },
    "attribution": { "agent_lines": 2, "human_added": 1, "agent_percentage": 50.0, ... },
    "summary": { "intent": "...", "outcome": "..." }
  }
}]
```

### `GET /api/sessions`
Lists active sessions from `.git/entire-sessions/*.json`.

**Response shape:**
```json
[{
  "session_id": "33fbc7e4-...",
  "phase": "ACTIVE",
  "agent_type": "Claude Code",
  "started_at": "2026-02-20T12:05:09Z",
  "first_prompt": "I'm using this project...",
  "step_count": 3,
  "base_commit": "c780808...",
  "files_touched": ["main.go", "README.md"]
}]
```

## Go Implementation (`main.go`)

### Structs (mirror the actual JSON from the CLI)

```go
// From checkpoint metadata on entire/checkpoints/v1
type CheckpointMetadata struct {
    Strategy         string       `json:"strategy"`
    CheckpointsCount int          `json:"checkpoints_count"`
    FilesTouched     []string     `json:"files_touched"`
    Agent            string       `json:"agent"`
    SessionID        string       `json:"session_id"`
    CreatedAt        string       `json:"created_at"`
    TokenUsage       *TokenUsage  `json:"token_usage,omitempty"`
    Attribution      *Attribution `json:"initial_attribution,omitempty"`
    Summary          *Summary     `json:"summary,omitempty"`
}

type TokenUsage struct {
    InputTokens         int `json:"input_tokens"`
    CacheCreationTokens int `json:"cache_creation_tokens"`
    CacheReadTokens     int `json:"cache_read_tokens"`
    OutputTokens        int `json:"output_tokens"`
    APICallCount        int `json:"api_call_count"`
}

type Attribution struct {
    AgentLines      int     `json:"agent_lines"`
    HumanAdded      int     `json:"human_added"`
    HumanModified   int     `json:"human_modified"`
    TotalCommitted  int     `json:"total_committed"`
    AgentPercentage float64 `json:"agent_percentage"`
}

type Summary struct {
    Intent  string `json:"intent"`
    Outcome string `json:"outcome"`
}
```

### Key Functions

| Function | What it does |
|----------|-------------|
| `main()` | Parse `-port` flag (default 8080), register routes, start server |
| `handleCheckpoints()` | Run `git log`, parse trailers, enrich with metadata, return JSON |
| `handleSessions()` | Read `.git/entire-sessions/*.json`, parse, return JSON |
| `gitLog(limit)` | Shell out to `git log --format=...`, parse null-separated output |
| `readCheckpointMeta(id)` | `git show entire/checkpoints/v1:<shard>/<rest>/0/metadata.json` |
| `gitCommonDir()` | `git rev-parse --git-common-dir` (cached) |

### Error Handling
- Git command failures return empty arrays (not 500s)
- Individual metadata read failures skip that checkpoint (show "no metadata" in UI)
- Server prints errors to stderr, keeps running

## Frontend (`index.html`)

### Layout
- **Header**: "Checkpoint Viewer" + current branch name + auto-refresh indicator
- **Active Sessions** section (top): cards showing phase, agent, prompt, step count
- **Checkpoint Timeline** section: commit cards with inline metadata

### Each Checkpoint Card Shows
- Commit short hash + subject + relative time
- Checkpoint ID badge
- Agent name + strategy
- Files touched as pills/tags
- Token usage (input/output/api calls) as compact stats
- Attribution bar (agent% vs human%)
- Summary intent/outcome (if available)

### Tech
- Inline `<style>` and `<script>`, no external deps
- CSS custom properties for dark theme
- `fetch()` + `setInterval(fetchAll, 3000)` for polling
- `Intl.RelativeTimeFormat` for "2 minutes ago" timestamps
- Graceful empty states ("No checkpoints found", "No active sessions")
