**1. [e2e/tests/attach_test.go:72] `show-ref --verify` with short ref is fragile in legacy mode**

The code uses `testutil.CheckpointMetadataRef()` with `show-ref --verify`, which requires a full ref path. In legacy mode, `CheckpointMetadataRef()` returns `entire/checkpoints/v1` (a short ref, not `refs/heads/entire/checkpoints/v1`), so `show-ref --verify` will always fail. In v2 mode, `refs/entire/checkpoints/v2/main` is a full ref and works correctly.

```go
if _, refErr := testutil.GitOutputErr(s.Dir, "show-ref", "--verify", "--hash", testutil.CheckpointMetadataRef()); refErr == nil {
```

In practice this is correct because in legacy mode the ref genuinely does not exist yet at this point in the test (it's before the first commit that creates a checkpoint). But the code is misleading -- it appears to detect "ref exists" but actually always fails in legacy mode for the wrong reason.

Suggested fix: Use `rev-parse --verify` instead of `show-ref --verify`, since `rev-parse` resolves short refs. Or prepend `refs/heads/` in the legacy case.

**2. [e2e/testutil/repo.go:190-198] `checkpointsMode()` default case is redundant and masks invalid input**

```go
func checkpointsMode() string {
    switch mode := os.Getenv("E2E_CHECKPOINTS_MODE"); mode {
    case "", checkpointsModeLegacy:
        return checkpointsModeLegacy
    case checkpointsModeV2DualWrite, checkpointsModeV2Only:
        return mode
    default:
        return mode // silently passes through unknown values
    }
}
```

The `default` arm returns unknown modes as-is. `ApplySuiteCheckpointsMode()` catches these downstream with `t.Fatalf()`, but `primaryCheckpointRef()` silently falls back to v1 on unknown modes. This inconsistency means an invalid `E2E_CHECKPOINTS_MODE` value would fail in `ApplySuiteCheckpointsMode` during setup but silently use v1 refs in `primaryCheckpointRef` if that function were ever called before setup. The behavior is currently safe because setup always runs first, but the inconsistency is a maintenance hazard.

Suggested fix: Have `checkpointsMode()` return only known values and add a panic or explicit error for unknown modes, or add validation to `primaryCheckpointRef()` matching the other functions.
