# Plan: `entire trail` command

## Context

PR #738 in entire.io introduces a "Trails" system on the web — a branch-centric work tracking abstraction stored on an `entire/trails` orphan branch. Trails answer "why/what" (human intent) while Checkpoints answer "how/when" (machine snapshots). They're linked by branch name.

This plan adds the CLI counterpart: an `entire trail` command that creates and manages trail metadata locally in git. When pushed (via pre-push hook), the web UI picks it up via webhooks automatically. Additionally, trails are auto-created when an agent session starts on a non-main branch.

## Command Structure

```
entire trail              # Show current branch's trail (or list if none)
entire trail list          # List all trails (with optional --status filter)
entire trail create        # Create a trail for current or new branch
entire trail update        # Update trail metadata (status, title, etc.)
```

## Key Design Decisions

- **Storage**: Dedicated `entire/trails` orphan branch (matches web PR)
- **ID format**: 12 hex char IDs with `<id[:2]>/<id[2:]>/` sharding (same as checkpoints)
- **Auto-create**: On session start (UserPromptSubmit hook), if on a non-main branch without a trail, auto-create one with status `in_progress`
- **Push**: Pre-push hook pushes `entire/trails` alongside `entire/checkpoints/v1`
- **Linking**: Trail ↔ Checkpoints linked by branch name (no foreign key)

## Data Format

### `entire/trails` branch structure
```
<trail_id[:2]>/<trail_id[2:]>/
  metadata.json
  discussion.json    # Empty initially, comments come later
```

### `metadata.json` (matches web PR format)
```json
{
  "trail_id": "abcdef123456",
  "branch": "feature/auth",
  "base": "main",
  "title": "Add user authentication",
  "description": "",
  "status": "in_progress",
  "author": "alice",
  "assignees": [],
  "labels": [],
  "created_at": "2026-02-18T10:30:00Z",
  "updated_at": "2026-02-20T14:22:00Z"
}
```

### Trail Status Lifecycle
```
draft → open → in_progress → in_review → done → closed
```

### 3. Create trail command
**New file**: `cmd/entire/cli/trail_cmd.go`

#### `entire trail` (root, no subcommand)
- If on a branch with a trail → show trail details (title, status, branch, base, timestamps)
- If no trail for current branch → fall through to `entire trail list` output

#### `entire trail list`
- Scan `entire/trails` branch, list all trails
- Flags: `--status <status>` (filter), `--json` (JSON output)
- Table output: branch, title, status, author, created_at

#### `entire trail create`
- Interactive mode (default): prompt for title, description, base branch
  - Title defaults to `HumanizeBranchName(currentBranch)`
  - Base defaults to detected default branch — reuse `strategy.GetDefaultBranchName()` (`cmd/entire/cli/strategy/common.go:1447`)
  - Uses `NewAccessibleForm()` for accessibility (`cmd/entire/cli/utils.go`)
- Non-interactive flags: `--title`, `--description`, `--base`, `--branch`, `--status`
  - If `--branch` specified and branch doesn't exist, create it via `git checkout -b`
  - If no `--branch`, use current branch via `GetCurrentBranch()` (`cmd/entire/cli/git_operations.go:156`)
  - Error if on main/master — use `IsOnDefaultBranch()` (`cmd/entire/cli/git_operations.go:83`)
- Initial status: `StatusDraft` for explicit create, `StatusInProgress` for auto-create

#### `entire trail update`
- Requires being on a branch with a trail (or `--branch` flag)
- Flags: `--status`, `--title`, `--description`, `--label add:X`, `--label remove:X`
- Updates `updated_at` timestamp automatically

### 4. Auto-create trail on session start
**File**: `cmd/entire/cli/lifecycle.go` — in `handleLifecycleTurnStart()` (line 112)

Insert after session initialization (line ~145), before return:
1. Get current branch via `GetCurrentBranch()` (`cmd/entire/cli/git_operations.go:156`)
2. Check if on default branch via `IsOnDefaultBranch()` — skip if true or error
3. Open trail store, call `FindByBranch(ctx, branchName)`
4. If trail already exists, skip
5. If no trail, auto-create:
   - Trail ID: `trail.GenerateID()`
   - Branch: current branch name
   - Base: `strategy.GetDefaultBranchName(repo)` — need to open repo first
   - Title: `trail.HumanizeBranchName(branchName)`
   - Status: `trail.StatusInProgress`
   - Author: git user.name from `checkpoint.GetGitAuthorFromRepo()`
6. Write trail via store
7. Log: `fmt.Fprintf(os.Stderr, "[entire] Created trail for branch: %s\n", branchName)`
8. Non-blocking: wrap in helper, log errors but don't fail the session
