## New Findings

### Important (Should Fix)

**[Task 16 `hook.go`] `CheckAndNotify` is defined but never wired into the session lifecycle.** The function exists and state persistence exists, but no task shows where `CheckAndNotify` is actually called from the existing hook handlers (e.g., `manual_commit_hooks.go`). The session phase state machine dispatches actions on `TurnEnd`/`SessionStop` events, and this is where the evolve trigger needs to be invoked. Without wiring, the evolve feature is complete but inert. The implementer will need to add a step that loads the evolve state, calls `CheckAndNotify`, and saves back -- likely in the `Stop` hook handler.

**[Task 14b `state.go` line 2880] `SaveState` does not ensure `.entire/` directory exists.** `os.WriteFile` will fail if `.entire/` is missing. The test masks this by calling `os.MkdirAll` explicitly. `LoadState` handles missing files, but `SaveState` should either document the prerequisite or defensively create the directory. In practice `.entire/` usually exists, but the defensive approach is better.

### Suggestions (Consider)

**[Task 6 line 1327-1330] Score ordering assumes chronological results.** `runInsights` truncates with `scores[len(scores)-last:]` assuming newest-last. But `ListCommitted` walks git tree entries sharded by checkpoint ID prefix, which has no guaranteed time order. Scores should be sorted by date before truncating.

**[Task 6 and 12] `ReadCommitted` returns `nil, nil` for missing checkpoints.** The plan handles this with `if err != nil || summary == nil { continue }`, which is correct, but silently skips failures. If many checkpoints are unreadable, users get partial results with no indication. A debug log would help diagnostics.
