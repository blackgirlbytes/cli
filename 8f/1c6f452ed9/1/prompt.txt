### TL;DR rationale
Two worktrees of the same repo can sit on the same base commit. Before this change the shadow branch was named purely from the commit hash (`entire/&lt;commit[:7]&gt;`), so two worktrees collided on a single git ref — a session starting in worktree B saw worktree A's shadow branch and threw a spurious "Shadow branch conflict detected." The fix gives each worktree its own ref namespace by appending a 6-hex-char SHA-256 hash of the internal git worktree ID (the directory name under `.git/worktrees/`, which is stable across `git worktree move`). The empty worktree ID (main worktree) hashes deterministically too, so main and linked worktrees coexist without special-casing. Cross-worktree `ShadowBranchConflictError` was deleted as no longer reachable; same-worktree `SessionIDConflictError` was preserved.</result>
