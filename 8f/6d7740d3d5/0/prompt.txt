## Review Findings

### 1. Redundant state mutation -- side-effect-only call pattern

**Severity: Low**

In `CondenseSession` (line 127-129 of `manual_commit_condensation.go`):

```go
if resolved, resolveErr := resolveTranscriptPath(state); resolveErr == nil {
    _ = resolved // state.TranscriptPath already updated by resolveTranscriptPath
}
```

The `_ = resolved` with an explanatory comment is a code smell but is functionally correct. The function serves two purposes: it returns the path AND mutates `state.TranscriptPath`. At this call site, only the mutation matters. The comment makes the intent explicit.

However, the dual-purpose design (return value + side effect) violates the principle of least surprise. A reader must understand that calling this function "just for the side effect" is intentional. Consider either:
- Splitting into `resolveTranscriptPath(state) (string, error)` (pure, no mutation) and a separate `updateTranscriptPathIfNeeded(state)` (mutation only), or
- Documenting the side-effect-only call pattern as an acceptable usage in the function's godoc.

The existing godoc does describe the mutation, so this is minor. The pattern is safe because `state` is always a pointer to a mutable struct that gets saved later via `saveSessionState`.

### 2. Copy-paste boilerplate across 3 hooks call sites

**Severity: Medium**

The three call sites in `manual_commit_hooks.go` follow an almost identical pattern:

```go
// hasNewTranscriptWork (line 1490)
if _, resolveErr := resolveTranscriptPath(state); resolveErr != nil {
    logging.Debug(logCtx, "hasNewTranscriptWork: transcript path resolution failed", ...)
    return false

// extractModifiedFilesFromLiveTranscript (line 1559)

    logging.Debug(logCtx, "extractModifiedFilesFromLiveTranscript: transcript path resolution failed", ...)

    logging.Warn(logCtx, "finalize: transcript path resolution failed, skipping", ...)
    state.TurnCheckpointIDs = nil
```

These share the same resolve-log-bail structure but differ in:
- Log message prefix (function name)
- Log level (Debug vs Warn)
- Return value type (bool vs []string vs int)

**Severity: Low**

In `CondenseSession`:

- Line 147: Calls `extractSessionDataFromLiveTranscript(ctx, state)` which calls `resolveTranscriptPath(state)` again (line 526).

**Severity: Medium**

### 5. `strings.TrimSuffix(base, filepath.Ext(base))` with multi-dot filenames

**Severity: Medium**

At line 46 of `resolve_transcript.go`:

```go
base := filepath.Base(state.TranscriptPath)
agentSessionID := strings.TrimSuffix(base, filepath.Ext(base))
```

`filepath.Ext` returns the extension from the *last* dot. For `session.backup.jsonl`, `filepath.Ext` returns `.jsonl`, so `TrimSuffix` produces `session.backup`. This is passed to `ag.ResolveSessionFile(sessionDir, "session.backup")`.

Looking at the actual agent implementations:
- **Claude Code**: `sessionDir + "/" + agentSessionID + ".jsonl"` -- would produce `session.backup.jsonl` (correct, same as input)
- **Cursor**: Same pattern, plus nested check with `sessionDir/session.backup/session.backup.jsonl`
- **Copilot CLI**: `sessionDir + "/" + agentSessionID + "/events.jsonl"` -- completely different filename, so the session ID is used as a directory name, not a file stem. Multi-dot is safe.
- **Gemini CLI**: Takes first 8 chars of agentSessionID and searches for `session-*-<8chars>.json`. Multi-dot IDs would still work.

In practice, agent session IDs are UUIDs (e.g., `87874108-eff2-47a0-b260-183961dd6cb0`) or date-prefixed UUIDs. They never contain dots. So this is not a real bug today.

However, the code has an implicit assumption that transcript filenames have a single-dot extension. If a future agent used a format like `session-2026.03.16.jsonl`, this would break -- `filepath.Ext` returns `.jsonl`, `TrimSuffix` produces `session-2026.03.16`, which is fine. But if the format were `session.2026-03-16.jsonl.gz` (double extension), `filepath.Ext` returns `.gz`, and the resulting ID `session.2026-03-16.jsonl` would be wrong.

The more defensive approach would be `strings.TrimSuffix(base, ".jsonl")` with a known-extension check, or using `strings.Cut` to split at the first dot. But given current agent ID formats, this is a latent concern rather than an active bug.
