on the pi changes, what are your thoughts on: 

Findings:

1. `agents/entire-agent-pi/internal/pi/paths.go:33` breaks the `resolve-session-file` protocol contract by ignoring the `sessionDir` argument for live-file fallback and instead using `protocol.RepoRoot()`. The protocol handler only passes `--session-dir` and `--session-id` ([protocol.go:107]( /Users/soph/Work/entire/devenv/external-agents/agents/entire-agent-pi/internal/protocol/protocol.go:107 )), so callers can legally ask the binary to resolve a session for a repo other than the process cwd. In that case this change searches `~/.pi/agent/sessions` under the wrong repo key and returns a false miss. The new tests only cover the case where `ENTIRE_REPO_ROOT == repoPath`, so this regression is currently untested. The fallback should derive the repo root from `sessionDir` instead of global process state.

2. `agents/entire-agent-pi/internal/pi/paths.go:99` can panic if `DirEntry.Info()` fails while sorting matches. That can happen if Pi is rotating/deleting session files between `os.ReadDir` and the later stat calls. Right now both errors are ignored and `ii.ModTime()` / `jj.ModTime()` will dereference `nil`. Since this code is explicitly reading a live session directory, it should treat `Info()` failure as a soft miss and continue, not crash `entire attach`.

Open question:

- Was the intent that `resolve-session-file` only ever runs from the target repo root? If so, the protocol surface does not enforce that today, and the Pi implementation is now depending on an implicit condition that the generic handler does not provide.

Validation:

- `go test ./...` in `agents/entire-agent-pi` currently fails, but due to an unrelated pre-existing mismatch in `TestGenerateExtension`, not this patch.
