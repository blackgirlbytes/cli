# Plan: Update Agent Integration Skill to E2E-Driven TDD

## Context

The agent integration skill currently uses unit-test-driven development in its implement phase (Phase 3). The user wants to flip this: **E2E tests become the primary spec**, and unit tests are written *after* each E2E test passes to lock in behavior. This makes the implementation more grounded in real behavior and uses `/debug-e2e` as the primary debugging tool.

Only the **implementer.md** file needs to change — the research and write-tests phases remain as-is. The SKILL.md orchestrator also stays the same since it just delegates to the procedure files.

Replace the current unit-test-first TDD cycles (Steps 4-9) with an E2E-test-driven progression:

### New implementer.md Structure

**Steps 1-2: Unchanged** — Read implementation guide + reference implementation (these provide essential context)

**Step 3: Create bare-minimum package that compiles** — All interface methods as stubs. Wire up blank imports in `hooks_cmd.go` and `config.go`. Run `mise run fmt && mise run lint && mise run test` to verify compilation.

**Step 4: E2E Tier 1 — `TestHumanOnlyChangesAndCommits`** — No agent prompt needed. Requires real `InstallHooks()`, basic `ParseHookEvent()`, `AreHooksInstalled()`. After passing, write `hooks_test.go` and initial `lifecycle_test.go` unit tests.

**Step 6: E2E Tier 2b — `TestCheckpointMetadataDeepValidation`** — Validates transcript quality (JSONL validity, content hash, prompts). May expose bugs in transcript formatting.

**Step 7: E2E Tier 3 — `TestSingleSessionAgentCommitInTurn`** — Agent creates + commits in one prompt. Tests in-turn commit path. Usually no new agent code needed.

**Step 8: E2E Tier 4 — Multi-session tests** — `TestMultiSessionManualCommit`, `TestMultiSessionSequential`, `TestEndedSessionUserCommitsAfterExit`.

**Step 9: E2E Tier 5 — Edge cases** — `TestModifyExistingTrackedFile`, `TestUserSplitsAgentChanges`, `TestDeletedFilesCommitDeletion`, etc.

**Step 10: Optional interfaces** — `TranscriptPreparer`, `TokenCalculator`, `SubagentAwareExtractor` based on research feasibility.

**Step 11: E2E Tier 6 — Interactive + rewind tests** — If agent supports interactive mode.

**Step 12: E2E Tier 7 — Complex scenarios** — Stash workflows, rapid commits, subagent flows.

**Steps 13-14: Register/wire up + final validation** — Same as current.

### Key Principles Embedded in Each Step

Each E2E tier follows the same cycle:
1. **Run the E2E test** — `mise run test:e2e:$AGENT_SLUG TestName`
2. **See it fail** — read the failure output
3. **Use `/debug-e2e {artifact-dir}`** to understand what happened
4. **Implement the minimum code** to make it pass
5. **Run again** until it passes
6. **Write unit tests** to lock in the behavior
