Now, all the feedback is about the issue of the tty options. 
1. MaybeAutoUpdate decides interactivity solely via stdoutIsTerminal() which checks os.Stdout, ignoring the passed w and also ignoring whether os.Stdin is a TTY. This can trigger an interactive huh prompt even when the caller has redirected output (e.g. Cobra cmd.SetOut(&bytes.Buffer) in versioncheck_test.go) or when stdin is piped, which can hang tests/local runs or consume piped input. Consider gating on the actual output writer when it’s an *os.File (and treating non-*os.File writers as non-interactive), and also requiring os.Stdin to be a terminal before running the confirm form.
2. Adding MaybeAutoUpdate(ctx, w, currentVersion) to CheckAndNotify means the existing TestCheckAndNotify_PrintsNotificationWhenOutdated test now exercises the interactive auto-update prompt path. The setupCheckAndNotifyTest helper doesn't set ENTIRE_NO_AUTO_UPDATE, doesn't mock stdoutIsTerminal, and doesn't mock confirmUpdate. On a developer machine where CI is unset and stdout happens to be a real terminal (e.g. running the compiled test binary directly), realConfirmUpdate renders a huh interactive form and the test hangs waiting for input. This passes in CI (where CI=true) but can fail locally.

3. defaultStdoutIsTerminal only checks term.IsTerminal on stdout, but the codebase's established hasTTY() function also guards against coding agent subprocesses (GEMINI_CLI, COPILOT_CLI, PI_CODING_AGENT, GIT_TERMINAL_PROMPT=0) that inherit the user's TTY yet cannot respond to interactive prompts. The new auto-update prompt can fire and block indefinitely in these agent environments since none of those env vars are checked and agents don't set CI.

 Step 1: Rewrite interactive/interactive.go — single source of TTY truth

 File: cmd/entire/cli/interactive/interactive.go

 Replace the current implementation with:

 package interactive

 import "os"

 // canPrompt is the TTY detection function. Swappable in tests via OverrideForTest.
 var canPrompt = checkCanPrompt

 // CanPromptInteractively reports whether interactive prompts can be shown.
 // Returns false when there is no controlling terminal, or when running
 // inside an AI agent subprocess that inherits the user's TTY but cannot
 // respond to prompts.
 func CanPromptInteractively() bool {
        return canPrompt()
 }

 func checkCanPrompt() bool {
        // Agent subprocesses may inherit the user's TTY but cannot respond
        // to interactive prompts. Detect known agents and bail out.
        if isAgentSubprocess() {
                return false
        }

        tty, err := os.OpenFile("/dev/tty", os.O_RDWR, 0)
        if err != nil {
                return false
        }
        _ = tty.Close()
        return true
 }

 // isAgentSubprocess returns true when the process is a subprocess of a known
 // AI coding agent. These agents may pass through the user's TTY but cannot
 // respond to interactive prompts on the user's behalf.
 func isAgentSubprocess() bool {
        if os.Getenv("GEMINI_CLI") != "" {
                return true
        }
        if os.Getenv("COPILOT_CLI") != "" {
                return true
        }
        if os.Getenv("PI_CODING_AGENT") != "" {
                return true
        }
        if os.Getenv("GIT_TERMINAL_PROMPT") == "0" {
                return true
        }
        return false
 }

 // OverrideForTest replaces TTY detection for the duration of a test.
 // Returns a restore function that must be deferred.
 //
 //     restore := interactive.OverrideForTest(func() bool { return false })
 //     defer restore()
 func OverrideForTest(fn func() bool) func() {
        old := canPrompt
        canPrompt = fn
        return func() { canPrompt = old }
 }

 Key points:
 - Agent-detection logic moves here FROM strategy/manual_commit_hooks.go:hasTTY()
 - ENTIRE_TEST_TTY env var is gone — replaced by OverrideForTest()
 - OverrideForTest is exported so all packages can use it

 // Form wraps huh.Form with automatic TTY detection.
 // When no controlling terminal is available, Run() returns nil
 // and all field values remain at their defaults.
 type Form struct {
        inner *huh.Form
 }

 // NewForm creates a new Form with the Entire theme applied.
 // The form will only run if a TTY is available.
 func NewForm(groups ...*huh.Group) *Form {
        return &Form{
                inner: huh.NewForm(groups...).WithTheme(entireTheme()),

 // Run executes the form if a TTY is available. Returns nil immediately

 func (f *Form) Run() error {
        if !interactive.CanPromptInteractively() {
                return nil
        }
        return f.inner.Run()
