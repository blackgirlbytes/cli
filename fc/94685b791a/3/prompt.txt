# Backfill Script: Index Checkpoints into Turbopuffer

## Context

The frontend currently has client-side string matching over checkpoint prompts, commit messages, and authors. We want to add full-text + semantic search over checkpoints, sessions, and transcripts using Turbopuffer. This plan covers **Part 1 only**: a one-time backfill script that reads existing checkpoint data from PlanetScale (and optionally transcript content from GitHub) and upserts it into Turbopuffer with embeddings.

## Script Location & Pattern

**File**: `entire.io/api/scripts/backfill-search.ts`

Follows the existing script pattern (`scripts/migrate.ts`, `scripts/reset.ts`):
- Standalone TypeScript script run via `npx tsx scripts/backfill-search.ts`
- Reads `DATABASE_URL` from env (defaults to local Docker MySQL)
- Direct PlanetScale connection via `mysql2` + `kysely` (not Hyperdrive)
- Reads `TURBOPUFFER_API_KEY` and `OPENAI_API_KEY` from env
- Optional `GITHUB_TOKEN` for transcript fetching

## New Dependencies

Add to `entire.io/api/package.json`:
```
"@turbopuffer/turbopuffer": "^0.2.x"
"openai": "^4.x"
```

These are used by the script only (not the Worker). They're devDependencies since the Worker doesn't need them at runtime yet (real-time indexing will add them to dependencies later).

## Document Schema in Turbopuffer

One namespace per repo: `checkpoints-{repo_id}`

Each document:
```
id:               uint   (auto-incrementing, derived from row order)
checkpoint_id:    string (12-hex-char, for linking back to frontend route)
branch:           string (for filtering)
agent:            string (for filtering)
author:           string (commit_author_username, for filtering)
created_at:       string (ISO timestamp, for sorting/filtering)
commit_sha:       string (for display)
commit_message:   string (stored for FTS)
prompt:           string (stored for FTS)
files_touched:    string (comma-joined paths, for FTS)
text:             string (concatenated searchable text, for FTS + vector)
```

The `text` field is what gets embedded. It's a concatenation of:
```
Prompt: {prompt}
Commit: {commit_message}
Files: {files_touched joined by ", "}
Transcript: {first user message + first assistant response, if available}
```

## Embedding Model

OpenAI `text-embedding-3-small` (1536 dimensions). Cheap, fast, good enough for POC. ~$0.02 per 1M tokens.

## Script Flow

```
1. Connect to PlanetScale
2. Query all repos with checkpoint_count > 0
3. For each repo:
   a. Create/get Turbopuffer namespace `checkpoints-{repo_id}`
   b. Query all checkpoints + commits for this repo (joined)
   c. Optionally fetch transcript excerpts from GitHub (--with-transcripts)
   d. Construct text field for each checkpoint
   e. Generate embeddings in batches (OpenAI batch API, 50 at a time)
   f. Upsert to Turbopuffer in batches
   g. Log progress
4. Print summary stats
```

### CLI Arguments

```
npx tsx scripts/backfill-search.ts [options]

Options:
  --repo <full_name>     Only backfill a specific repo (e.g., "entireio/cli")
  --with-transcripts     Fetch transcript excerpts from GitHub (slower, needs GITHUB_TOKEN)
  --dry-run              Show what would be indexed without writing to Turbopuffer
  --limit <n>            Max checkpoints per repo (for testing)
```

### Transcript Fetching (--with-transcripts)

When enabled, for each checkpoint:
1. Compute folder path: `{checkpoint_id[:2]}/{checkpoint_id[2:]}`
2. Fetch `{folder}/0/full.jsonl` from `entire/checkpoints/v1` branch via GitHub API
3. Parse with the appropriate agent transcript parser (reuse `getParserForAgent()`)
4. Extract first user message content + first assistant message content
5. Truncate to ~2000 chars combined to stay within embedding token limits
6. Append to the `text` field

This uses `GITHUB_TOKEN` (a PAT with repo read access). Rate limited to ~5000 req/hr. For repos with many checkpoints, this is the bottleneck — add a small delay between requests.

### `backfill-search.ts` Structure

```typescript
// 1. Imports & config
// 2. parseArgs() - CLI argument parsing
// 3. buildSearchText(checkpoint, transcriptExcerpt?) - construct text for embedding
// 4. generateEmbeddings(texts[]) - batch call to OpenAI
// 5. fetchTranscriptExcerpt(repoFullName, checkpointId, token) - GitHub API + parser
// 6. processRepo(db, repoId, repoFullName, options) - main per-repo logic
// 7. main() - orchestrator
```

Key implementation details:

- **DB query**: Join `repo_checkpoints` + `repo_checkpoint_commits` grouped by checkpoint_id (same pattern as `getCheckpointsForBranch` in `src/lib/planetscale/checkpoints.ts`)
- **Embedding batching**: OpenAI allows up to 2048 embeddings per request, but we batch at 50 to limit memory and provide progress feedback
- **Turbopuffer upsert**: Batch upsert with vectors + attributes. Turbopuffer's `upsert()` handles create-or-update automatically
- **Transcript parsers**: Import and reuse `getParserForAgent()` from `src/lib/transcript-parsers/`
- **GitHub API**: Reuse the same raw fetch pattern as `fetchFileAtCommit()` in `src/lib/github.ts`
- **Progress logging**: Log per-repo progress (checkpoints indexed, time taken)
- **Error handling**: Skip individual checkpoints on error (log warning), don't abort the whole repo

## Example Usage

```bash
# Backfill a single repo (quick test)
DATABASE_URL=mysql://... TURBOPUFFER_API_KEY=... OPENAI_API_KEY=... \
  npx tsx scripts/backfill-search.ts --repo entireio/cli --limit 10

# Backfill all repos, metadata only (no transcripts)
DATABASE_URL=mysql://... TURBOPUFFER_API_KEY=... OPENAI_API_KEY=... \
  npx tsx scripts/backfill-search.ts

# Backfill all repos with transcript excerpts
DATABASE_URL=mysql://... TURBOPUFFER_API_KEY=... OPENAI_API_KEY=... GITHUB_TOKEN=... \
  npx tsx scripts/backfill-search.ts --with-transcripts

# Dry run to see what would be indexed
DATABASE_URL=mysql://... TURBOPUFFER_API_KEY=... OPENAI_API_KEY=... \
  npx tsx scripts/backfill-search.ts --dry-run
```

## Verification

1. Run with `--dry-run --repo <your-test-repo>` to verify data extraction looks correct
2. Run with `--repo <your-test-repo> --limit 5` to index a small batch
3. Verify in Turbopuffer dashboard that the namespace exists with correct document count
4. Test search manually via Turbopuffer API/dashboard to confirm FTS + vector results return relevant checkpoints
5. Run full backfill once satisfied
