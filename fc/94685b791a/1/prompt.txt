# Enhanced Search Experience for Checkpoints

## Context

Search currently returns results with no indication of *why* they matched. The checkpoint cards look identical to the normal list — no highlighted terms, no visible prompt, no match source. Turbopuffer returns rich RRF metadata (`rrf` score, `vectorRank`, `bm25Rank`) but it's discarded before reaching the frontend.

Goal: Users should immediately understand why each search result appeared — highlighted terms, visible prompts, and match type indicators.

## Changes

### 1. Backend: Return RRF metadata from search

**`api/src/lib/turbopuffer.ts`**
- Change `searchCheckpoints()` return type from `TurbopufferSearchResult[]` to `RRFResult[]`
- Line 311: `return merged;` instead of `return merged.map((r) => ({ checkpoint_id: r.checkpoint_id }))`

**`api/src/routes/cache.ts` (search route, ~line 2381-2418)**
- Build `searchMeta` map from RRF results:
  ```typescript
  const searchMeta: Record<string, { matchType: "semantic" | "keyword" | "both"; score: number }> = {};
  for (const r of searchResults) {
    const matchType = r.vectorRank != null && r.bm25Rank != null ? "both"
      : r.vectorRank != null ? "semantic" : "keyword";
    searchMeta[r.checkpoint_id] = { matchType, score: r.rrf };
  }
  ```
- Add `searchMeta` to the JSON response

### 2. Frontend: Types

**`frontend/src/domains/platform/checkpoints/api.ts`**
- Add `SearchMeta` type: `{ matchType: "semantic" | "keyword" | "both"; score: number }`
- Add `SearchCheckpointsResponse extends CheckpointsResponse` with optional `searchMeta` map
- Add `filesTouched: string[] | null` to `CheckpointInfo` (already sent by backend, just untyped)
- Update `searchCheckpoints()` return type to `SearchCheckpointsResponse`

**`frontend/src/domains/platform/checkpoints/hooks/useCommitsQuery.ts`**
- Update `useSearchCheckpointsQuery` to use `SearchCheckpointsResponse` type

### 3. Frontend: HighlightText component

**New file: `frontend/src/components/HighlightText.tsx`**
- Props: `text`, `query`, `className?`, `highlightClassName?`
- Splits query into words, escapes regex specials, wraps matches in `<mark>` elements
- Default highlight: `bg-yellow-200/60 dark:bg-yellow-800/40 rounded-sm px-0.5`
- Returns plain `<span>` when no query — safe to use unconditionally

### 4. Frontend: Enhanced search result cards

**`frontend/src/domains/platform/checkpoints/pages/CheckpointsPage.tsx`**

Pass `searchQuery` and `searchMeta` to `CheckpointsList`. When in search mode, each card gains:

1. **Highlighted commit message** — wrap title in `<HighlightText>` with the search query
2. **Prompt subtitle** — show first session prompt (truncated ~120 chars) with highlighted terms, in `text-muted`. Only when prompt exists.
3. **Match type badge** — next to checkpoint ID badge:
   - "Semantic + Keyword" (blue) — matched both ways
   - "Semantic" (purple) — conceptually related, no exact term match
   - "Keyword" (green) — exact term match in indexed text
4. **Matched files** — if query terms appear in `filesTouched`, show up to 3 matching filenames with highlights

When not in search mode, rendering is identical to current (zero regression).

## Card Layout (search mode)

```
┌──────────────────────────────────────────────────────────────────┐
│ Implement [login] feature with OAuth                             │ ← highlighted
│ "Add [login] page with Google OAuth integration..."              │ ← prompt
│ a3b2c4d5e6f7 · Semantic + Keyword · 2h ago · @user · Claude     │
│                                    +42 -8 · 3 files · 1 session │
│ auth.ts, [login].tsx                                             │ ← matched files
└──────────────────────────────────────────────────────────────────┘
```

## Edge Cases

- **No prompt**: Prompt line omitted, card shows title + match type only
- **Semantic-only match**: No terms highlighted (expected), "Semantic" badge explains why result appeared
- **Long prompts**: Truncated to 120 chars + "...", CSS `truncate` as backup
- **Special chars in query**: Regex specials escaped in HighlightText (e.g., "file.ts" works)
- **`filesTouched` is null**: Matched files section omitted entirely
