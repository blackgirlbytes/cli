# Wire Up Checkpoint Search via Turbopuffer

## Context

Checkpoints have been backfilled into Turbopuffer (namespace `checkpoints-{repo_id}`) with embeddings and attributes. The frontend currently does client-side string matching over prompts, commit messages, and authors. We need to:

1. Add a search API endpoint that queries Turbopuffer
2. Replace the frontend's client-side filtering with API-driven search

## Approach

- **API**: Direct `fetch()` calls to Turbopuffer REST API from the Cloudflare Worker (no new runtime dependencies)
- **Frontend**: Replace client-side filter entirely — when search input is non-empty, call the search endpoint; when empty, show the normal checkpoint list

## Implementation Details

### 1. Turbopuffer REST Client (`api/src/lib/turbopuffer.ts`)

Thin wrapper around Turbopuffer's REST API using `fetch()`. No SDK needed.

```typescript
export interface TurbopufferSearchResult {
  checkpoint_id: string;
  // other attributes returned for convenience
}

export async function searchCheckpoints(
  apiKey: string,
  repoId: string,
  query: string,
  filters?: { branch?: string },
  limit?: number,
): Promise<TurbopufferSearchResult[]>
```

**Turbopuffer REST endpoint**: `POST https://api.turbopuffer.com/v1/vectors/checkpoints-{repo_id}/query`

**Request body** — use BM25 full-text search on the `text` attribute + optional attribute filters:
```json
{
  "top_k": 50,
  "rank_by": ["text", "BM25", "search query here"],
  "filters": {
    "branch": [["Eq", "main"]]
  },
  "include_attributes": ["checkpoint_id"]
}
```

Returns `checkpoint_id` values which we use to fetch full checkpoint data from PlanetScale.

### 2. Env Update (`api/src/env.ts`)

Add `TURBOPUFFER_API_KEY?: string` as optional to the `Env` interface. Not added to `REQUIRED_ENV_VARS` since search is an optional feature — the endpoint returns 503 if the key is missing.

### 3. Search API Endpoint (`api/src/routes/cache.ts`)

New route on `repoRoutes`: `GET /:org/:repo/checkpoints/search?q=<query>&branch=<branch>`

**Flow**:
1. Validate `q` param (required, non-empty)
2. Check repo access (reuse existing `checkRepoAccess()` helper)
3. If `TURBOPUFFER_API_KEY` not set, return 503
4. Call `searchCheckpoints()` with `repoRecord.id`, query, and optional branch filter
5. Get the `checkpoint_id` list from results
6. Fetch full checkpoint data from PlanetScale using existing `db.checkpoints.getByIds(repoId, checkpointIds)`
7. Map through existing `mapCheckpointToInfo()` to build response
8. Return in same shape as the existing checkpoints endpoint for frontend compatibility

**Auth**: Same `optionalAuth + rateLimitUnauthenticated` pattern as existing checkpoint routes.

**Response**: Same `CheckpointsResponse` type so the frontend can render search results identically to the normal list.

### 4. Frontend API Function (`frontend/src/domains/platform/checkpoints/api.ts`)

Add:
```typescript
export async function searchCheckpoints(
  org: string, repo: string, query: string, branch?: string,
): Promise<CheckpointsResponse> {
  const params = new URLSearchParams({ q: query });
  if (branch) params.set("branch", branch);
  return request<CheckpointsResponse>(
    `/api/v1/cache/${org}/${repo}/checkpoints/search?${params.toString()}`
  );
}
```

Reuses the existing `CheckpointsResponse` type — no new response types needed.

### 5. Frontend Hook (`frontend/src/domains/platform/checkpoints/hooks/useCommitsQuery.ts`)

Add:
```typescript
export function useSearchCheckpointsQuery(
  org: string, repo: string, query: string, branch: string,
) {
  return useQuery<CheckpointsResponse>({
    queryKey: ["github", "checkpoints-search", org, repo, query, branch],
    queryFn: () => searchCheckpoints(org, repo, query, branch),
    enabled: query.trim().length > 0,
    staleTime: 30_000,
    placeholderData: (prev) => prev, // keep previous results while fetching
  });
}
```

### 6. Frontend Page (`frontend/src/domains/platform/checkpoints/pages/CheckpointsPage.tsx`)

Replace the client-side filter block (lines 82-95) with debounced API search:

- Add `useEffect`-based debounce (300ms) on `searchQuery` → `debouncedQuery`
- Call `useSearchCheckpointsQuery(org, repo, debouncedQuery, branch)`
- When `debouncedQuery` is non-empty, use search results; otherwise use normal checkpoint list
- Show subtle loading indicator while search is in flight
- Update "No matching checkpoints" empty state to work with search results

Key changes:
- Remove: the `allCheckpoints.filter(...)` client-side logic
- Add: `debouncedQuery` state + `useEffect` debounce
- Add: `useSearchCheckpointsQuery` hook call
- Modify: `checkpoints` derivation to branch on `isSearchActive`
