The abstraction and handling of remotes does not seem correct. checkpoint/remote is solely for the handling of checkpoint remote. And things like
  trail_cmd calls ResolveRemoteRepo which eventually ends up calling checkpoint/remote.

  A new abstraction/package should exist to provide the handling/interfacing with the primary repository, as opposed to the checkpoint repository.

RedactURL doesn’t correctly handle SSH SCP-style remotes like git@github.com:org/repo.git. url.Parse returns no error for that form (it treats git@github.com as the scheme), so this function currently returns a malformed string (e.g., git@github.com://) instead of a useful redaction. Add an explicit SCP-format check (similar to ParseURL) or additional validation of the parsed URL fields (e.g., empty host with non-empty opaque) and include a unit test for SCP-style URLs.
