### 1. **listCommittedForExplain Always Calls v1Store.ListCommitted() First**

- **v1 ListCommitted** (committed.go:1003): Walks the v1 metadata branch tree, reads metadata.json files for each checkpoint, extracts session metadata. It's a **full tree traversal reading JSON** for every checkpoint.

- Reading and parsing metadata.json for every checkpoint in both branches
- Only then deduping via the `seen` map

**Why it exists:** Lines 371-381 show the intent — during v1→v2 migration, old checkpoints might only exist on v1, so the code fetches both and merges. This is a **migration/transition concern**, not a permanent strategy.

**Verdict:** If `preferCheckpointsV2 = true`, callers expect v2 as the primary source. You could add a **conditional** to skip v1 entirely when v2 is preferred AND has checkpoints, only falling back if v2 is empty/fails. But the current approach is safe for transition.

### 2. **Debug Logging in ListCommitted Hot Callback**

**Finding: This is very cheap when disabled.**

Looking at logging.go:233-235:

```go
func Debug(ctx context.Context, msg string, attrs ...any) {
	log(ctx, slog.LevelDebug, msg, attrs...)
}

func log(ctx context.Context, level slog.Level, msg string, attrs ...any) {
	l := getLogger()
	// ... builds allAttrs ...
	l.Log(nil, level, msg, allAttrs...) // slog.Logger.Log checks level first
}
```

**How slog handles level checking:**
- `slog.Logger.Log()` (stdlib, line 299) checks the handler's level **before** processing any attributes
- If the log level is below the handler's threshold (e.g., DEBUG when handler is set to INFO), **attributes are never evaluated**
- The `slog.String()` calls (allocations) **happen before the level check** in your code, in the callback

**The issue:** In v2_read.go lines 88-90 and 100-102, you're calling:

```go
slog.String("checkpoint_id", checkpointID.String()),
slog.String("error", cpTreeErr.Error())
```

These allocate strings **unconditionally** in the argument list, even though slog will discard them if the level is filtered. The stdlib's `log/slog` package normally uses **lazy attribute evaluation** via functions to avoid this, but you're passing eager string allocations here.

**However, this is a **hot callback inside tree walk** — every checkpoint pays this cost if called, even if logging is INFO or WARN.**

**Verdict:** The attributes are created eagerly before slog sees them. For a hot path callback that fires once per checkpoint in ListCommitted:
- If you have 100 checkpoints and debug is disabled (INFO level), you still allocate 100+ temporary strings
- This is **not catastrophic** for `explain` (typically <100 checkpoints), but it's suboptimal
- **Better pattern:** Use conditional logging: `if getLogger().Enabled(ctx, slog.LevelDebug) { logging.Debug(...) }` or refactor to avoid the hot path entirely
