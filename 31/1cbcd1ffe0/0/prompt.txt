In push_common.go: ReconcileDisconnectedMetadataBranch always reconciles the local metadata branch (paths.MetadataBranchName), but here the remote ref passed in is derived from the generic branchName being synced. If fetchAndMergeSessionsCommon were ever used for a non-metadata branch, this would compare the metadata branch against an unrelated remote ref and could incorrectly cherry-pick onto that history. Consider either (a) guarding this call so reconciliation only runs when branchName == paths.MetadataBranchName, or (b) computing the remoteRefName specifically for the metadata branch (independent of branchName) to keep the function safe if reused.
