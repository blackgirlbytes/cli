  # Combined review:  checkpoint-export-cli  vs  entire-labs-plan

  Scope: 1 commit, 7 files, +894/-7. Adds machine-readable export modes:

  •  entire explain --json  (metadata-only envelope; list or single)
  •  entire explain --transcript [--session-index N]  (compact transcript
  stream)
  •  entire session info|current --transcript  (live raw agent transcript
  stream)
  Verdict: needs-attention. Substantial new public surface with three concrete
  bugs and several real smells. None are blockers if you're shipping behind
  the existing flag-gated CLI surface, but the JSON contract bugs will burn
  machine consumers.

  --------

  ## /review — overview

  What it does (well): additive surface, JSON envelope explicitly excludes raw
  transcript bytes, transcript bytes go to stdout via dedicated  --
  transcript / --raw-transcript  flags.  MarkFlagsMutuallyExclusive  enforces
  the trichotomy ( --json  /  --transcript  /  --raw-transcript ). Help text
  is clear, includes a security-relevant invariant ("Transcript bytes are
  NEVER embedded in the JSON envelope"). Tests for envelope-leak, mutual-
  exclusion, out-of-range index, and dispatch routing all present.
  What's missing:

  • No test for the partial-failure JSON shape (per-session metadata read
  fails → stub entry).
  • No test for  runExplainListJSON  non-context error path — currently
  silently emits  [] .
  • No test for cancellation mid- io.Copy  on a large transcript.

  ## /adversarial-review — material findings

  ### Finding A: JSON consumers cannot detect partial failure (data integrity)

   runExplainCheckpointJSON  and  runExplainListJSON  both swallow read errors
  and return success with degraded output. A CI script doing  entire
  checkpoint explain X --json | jq '.sessions[].agent'  will silently process
  stub entries with no  agent  field, producing an empty/null result
  indistinguishable from "agent unset". For a list query,  entire checkpoint
  explain --json  returning  []  could mean "no checkpoints exist" or "tree
  fetch failed". This violates the implicit contract of any  --json  flag:
  structured output should be lossless.

  • File/line:  explain_export.go:359-367 ,  446-458
  • Likely impact: silent CI / dashboard breakage; bug reports that look like
  "I lost data".
  • Fix: distinguish the two cases. Options: top-level  error  field, non-zero
  exit + JSON error to stderr, or per-session  error  field. Pick one and add
  a test.
  • Confidence: 0.85

  ### Finding B: Cancellation contract violation on transcript stream

   copySessionTranscript  accepts  ctx context.Context  but passes nothing
  through to  io.Copy . The single  ctx.Err()  check at entry is the only ctx-
  aware moment. For a user doing  entire session current --transcript >
  big.jsonl  on a multi-hour session with a >100MB transcript, Ctrl-C will not
  interrupt the copy — it will run to EOF first. Worse, the function signature
  implies cancellation works, so callers may not add their own watchdog.

  • File/line:  sessions.go:858-863
  • Likely impact: unkillable streams in interactive use; misleading API for
  future callers.
  • Fix: standard pattern — start a goroutine that closes  f  on  <-ctx.
  Done() .  io.Copy  then returns with an error.
  • Confidence: 0.9

  ### Finding C: TOCTOU / mid-line read race on live transcripts

   writeSessionTranscript  for  entire session current --transcript  opens the
  live transcript and  io.Copy s to current EOF. If the agent is mid-write of
  a JSONL line when the read happens, the consumer gets a truncated line.
  JSONL parsers will reject it. This is most likely on slow disks or when the
  agent buffers writes — Claude Code, Cursor, Gemini all stream-write JSONL
  but with implementation-specific buffering.

  • File/line:  sessions.go:927-948
  • Likely impact: intermittent JSON parse errors when streaming an active
  session. Hard to reproduce, easy to blame on the user.
  • Fix: document the snapshot semantics in the help text ("snapshot of the
  transcript at command start; partial trailing line possible if agent is mid-
  write"), or scan back to the last newline before EOF and trim. The latter is
  more robust.
  • Confidence: 0.65 (depends on agent write buffering, which varies by
  integration).

  ### Finding D:  resolveSessionIndex  conflates "checkpoint missing" with
  "checkpoint empty"

  When  summary != nil && len(summary.Sessions) == 0 , the function returns
   (0, ErrCheckpointNotFound) . But the checkpoint was found — it just has no
  sessions. Callers using  errors.Is(err, ErrCheckpointNotFound)  to drive UX
  (e.g., "did you mistype the ID?") will give wrong guidance.

  • File/line:  explain_export.go:230-232
  • Likely impact: confusing error UX for legitimate empty-checkpoint edge
  case; wrong fallback in upstream callers that branch on the sentinel.
  • Fix: return a distinct error (e.g., a new  ErrCheckpointHasNoSessions  or
  just  errors.New("checkpoint has no sessions")  — losing the sentinel here
  is fine because no caller currently branches on it for this code path).
  • Confidence: 0.7

  ### Finding E: Path-traversal nolint annotation overstates validation

   openSessionTranscript = func(path string) { return os.Open(path) }  is
  annotated  //nolint:gosec // path is resolved from validated session state .
  But  state.TranscriptPath  is just deserialized from  .git/entire-
  sessions/<id>.json  — there is no validation that it's confined to any
  directory or that it doesn't traverse symlinks. The realistic threat model
  is low (local user already has filesystem access), but the comment is wrong,
  and a future reader will trust it.

  • File/line:  sessions.go:852-854
  • Likely impact: documentation drift hides assumptions; if Entire ever gains
  a daemon mode or runs under a different uid, this becomes exploitable.
  • Fix: rewrite the comment to state the actual trust assumption (" state.
  TranscriptPath  is trusted because session state files are written
  exclusively by Entire under  .git/ ; this is not validated").
  • Confidence: 0.6

  ## Top recommended fixes (in order)

  1. Findings A + 1 — JSON envelope error semantics (per-session error field;
  non-empty list path returns errors instead of  [] ). Highest user-impact bug.
  2. Findings B + 1 — make  copySessionTranscript  ctx-aware (close-on-done
  goroutine pattern).
  3. Finding 4 — extract the  prefix-match + remote-fetch-on-miss  helper from
   explain.go  and  explain_export.go . ~25 lines deduped.
  4. Finding 5 — drop the  openSessionTranscript / copySessionTranscript
  indirections; they are dead test infra.
  5. Finding 6 + D — fix the misleading error message and the
   ErrCheckpointNotFound  conflation.
  6. Finding C — at minimum, document live-transcript snapshot semantics in  -
  -help . Trim-to-last-newline is the better fix.
  The rest are style/nits and can wait.
