The most likely issue is that the automation is assuming Copilot CLI local session storage exists inside the GitHub Copilot cloud agent runner, but those are not the same thing.

GitHub’s docs say ~/.copilot/session-state/ is where Copilot CLI persists session files locally on your machine for resume/history features. That is documented as local CLI storage, not as a guaranteed artifact path for cloud-agent jobs.

By contrast, for Copilot cloud agent, GitHub documents tracking via the session logs in GitHub, the agents tab, VS Code, Raycast, or gh agent-task view --log; the docs do not describe /home/runner/.copilot/session-state/.../events.jsonl as a supported cloud-agent log location.
