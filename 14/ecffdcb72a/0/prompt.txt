## Issue 1: No Active Session Protection in `--all` Path

**Location:** `/Users/peytonmontei/Documents/entire/devenv/entireio/cli/cmd/entire/cli/clean.go`, lines 68-69 (routing) and the `runCleanAll` function (line ~261 on PR branch)

**Severity:** CRITICAL

**Issue Description:** The `runCleanCurrentHead` path (no `--all` flag) has an active session guard at lines 99-114 that checks for ACTIVE-phase sessions and refuses to proceed without `--force`. The `runCleanAll` path bypasses this guard entirely. The new `ListAllItems` function returns ALL sessions regardless of phase, meaning `--all` will happily delete session state for a session that an agent is actively using RIGHT NOW, without any warning about active sessions (unless the user omits `--force`, in which case they get a generic confirmation prompt that does not distinguish active sessions from idle/ended ones).

**User Impact:** A user runs `entire clean --all --force` while an agent is mid-turn. The session state file is deleted. The agent's next lifecycle hook (e.g., `Stop`, `PostCommit`) tries to load session state, fails, and either errors cryptically or silently loses checkpoint data. The user has no idea their in-progress work was disrupted because no warning was shown.

**Recommendation:** Add an active session check to `runCleanAll` that mirrors the guard in `runCleanCurrentHead`. At minimum, warn the user about active sessions and require `--force` to override. Better yet, have `ListAllItems` annotate active sessions so the preview output distinguishes them (e.g., "Session X (ACTIVE -- agent may be running)").

## Issue 2: Grace Period Removed for All Sessions

**Location:** `/Users/peytonmontei/Documents/entire/devenv/entireio/cli/cmd/entire/cli/strategy/cleanup.go`, new `ListAllItems` function (lines 363-397 in the PR)

**Severity:** HIGH

**Issue Description:** The old `ListAllCleanupItems` called `ListOrphanedSessionStates` which has a 10-minute grace period (line 193: `if now.Sub(state.StartedAt) &lt; sessionGracePeriod`). This protects sessions that just started but haven't created their first checkpoint yet. The new `ListAllItems` function iterates `store.List(ctx)` directly and adds every session unconditionally -- no grace period check. The brand-new session state is deleted before the agent can save its first checkpoint. The agent then operates in a ghost state -- it may continue running but all checkpoint/session tracking is broken.

## Issue 3: Orphaned Temp Files When Deleting Active Sessions

**Location:** `/Users/peytonmontei/Documents/entire/devenv/entireio/cli/cmd/entire/cli/clean.go`, `listTempFiles` (line 449) and `runCleanAll` (line ~261)

**Severity:** HIGH

**Issue Description:** This is the specific interaction you asked about. `listTempFiles` builds a set of active session IDs (line 463-468) and SKIPS temp files belonging to those sessions (lines 479-484). But `ListAllItems` lists those same sessions for deletion. The execution order in `runCleanAll` is:

1. `ListAllItems` returns all sessions (including active ones)
2. `listTempFiles` sees those sessions as active and skips their temp files
3. `DeleteAllCleanupItems` deletes the session state files
4. The temp files that were skipped in step 2 are now orphaned -- the session state is gone but the temp files remain

These orphaned temp files will never be cleaned up by a future `--all` run because the same race exists: `listTempFiles` checks for active sessions at listing time, but by the time deletion happens, the state is gone. Actually, on a FUTURE run there would be no session state, so `listTempFiles` would NOT skip them. But on THIS run, the temp files are missed. The user would need to run `--all` again to catch them.

**User Impact:** After a `clean --all`, leftover temp files in `.entire/tmp/` accumulate. Not catastrophic, but it contradicts the "clean ALL data" promise of the flag. A user who expects a complete cleanup will have stale data left behind with no indication.

**Recommendation:** Either (a) list temp files AFTER the session state deletion (not before), or (b) when `--all` is specified, do not filter temp files by active session (since those sessions are about to be deleted anyway). The simplest fix: in `runCleanAll`, pass a flag or use a separate code path for `listTempFiles` that skips the active-session filtering when performing a full cleanup.
