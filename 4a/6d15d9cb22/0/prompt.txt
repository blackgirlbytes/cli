# Droid Test Suite Assessment

## Context
Audit of all Factory AI Droid test files to determine whether they're testing meaningful behavior or are useless/redundant.

---

## File-by-File Assessment

### 1. `factoryaidroid_test.go` — Mixed quality (40% trivial, 60% useful)

**Genuinely useful tests:**
- `TestDetectPresence` — Tests real filesystem behavior with `.factory/` directory
- `TestReadTranscript` / `TestReadTranscript_MissingFile` — Tests file I/O and error path
- `TestChunkTranscript_LargeContent` — Tests non-trivial chunking at line boundaries
- `TestChunkTranscript_RoundTrip` — Tests the critical invariant: chunk + reassemble = original
- `REDACTED` — Tests JSON parsing with error cases
- `TestGetSessionDir` — Tests path sanitization logic (non-alphanumeric → `-`)
- `TestGetSessionDir_EnvOverride` — Tests env var override for testing

**Trivial / nearly useless tests (candidates for removal):**
- `TestName` — Tests `return agent.AgentNameFactoryAIDroid` (a constant)
- `TestType` — Tests `return agent.AgentTypeFactoryAIDroid` (a constant)
- `TestDescription` — Tests `desc != ""` (meaningless assertion)
- `TestGetHookConfigPath` — Tests `return ".factory/settings.json"` (a string literal)
- `TestSupportsHooks` — Tests `return true`
- `TestGetSessionID` — Tests `return input.SessionID` (single field access)
- `TestReadSession` / `TestWriteSession` — Tests that unimplemented stubs return errors; will need to be deleted when implemented, protects nothing meaningful
- `TestResolveSessionFile` — Tests `filepath.Join(dir, id+".jsonl")` (one-liner)
- `TestFormatResumeCommand` — Tests `"droid --session-id " + sessionID` (string concat)
- `TestChunkTranscript_SmallContent` — Trivial case (fits in one chunk), redundant with RoundTrip
- `TestReassembleTranscript_SingleChunk` / `TestReassembleTranscript_MultipleChunks` — Redundant with RoundTrip test

### 2. `lifecycle_test.go` — Solid (all tests are useful)

Every test validates the critical hook-name → event-type mapping, which is the core contract between the Droid agent and the Entire CLI framework:

- `TestParseHookEvent_SessionStart/TurnStart/TurnEnd/SessionEnd` — Each validates correct event type + field population
- `TestParseHookEvent_SubagentStart/SubagentEnd` — Tests ToolUseID and SubagentID extraction from structured JSON
- `TestParseHookEvent_Compaction` — Tests pre-compact hook mapping
- `TestParseHookEvent_SubagentStop_PassThrough` / `Notification_PassThrough` — Tests that acknowledged-but-no-action hooks correctly return nil
- `TestParseHookEvent_UnknownHook` — Tests graceful handling of future hooks
- `TestParseHookEvent_EmptyInput` / `MalformedJSON` — Tests error paths

**Verdict:** No changes needed. Every test validates meaningful behavior.

### 3. `transcript_test.go` — Strongest file (nearly all tests are high-value)

**High-value tests:**
- `TestParseDroidTranscript_NormalizesEnvelope` — **THE most important Droid test.** Validates the Droid-specific format transformation (outer `type:"message"` + inner `role` → normalized `type:role`). Without this, all transcript parsing breaks.
- `TestParseDroidTranscript_StartLineOffset` — Critical for incremental checkpoint processing
- `TestParseDroidTranscript_RealDroidFormat` — Integration-style test with tool_use content
- `TestCalculateTokenUsage_StreamingDeduplication` — Tests critical edge case where streaming creates duplicate message IDs
- `REDACTED` — Protects against a documented bug where files modified only by subagents get missed
- `TestExtractAllModifiedFilesFromTranscript_IncludesSubagentFiles` — Tests cross-agent file aggregation with actual filesystem
- `TestCalculateTotalTokenUsageFromTranscript_PerCheckpoint` — Tests per-checkpoint token calculation at different offsets
- `TestExtractSpawnedAgentIDs_FromToolResult` — Tests complex multi-layer JSON parsing

**Lower-value but still reasonable:**
- `TestSerializeTranscript` — Round-trip test, adds some value
- `TestExtractModifiedFiles_Empty` / `TestCalculateTokenUsage_EmptyTranscript` — Nil/zero boundary tests (low value but harmless)

**Verdict:** No changes needed. Very well-designed test file.

### 4. `hooks_test.go` — Excellent (almost all tests are critical)

**Critical tests (protect against data loss):**
- `TestInstallHooks_PreservesUserHooksOnSameType` — Prevents nuking user's existing hooks during install
- `TestInstallHooks_PreservesUnknownHookTypes` — Forward-compatibility with future hook types
- `TestInstallHooks_PermissionsDeny_PreservesUserRules` — Prevents removing user's security rules
- `TestInstallHooks_PermissionsDeny_PreservesUnknownFields` — Preserves unknown fields like `ask`
- `TestUninstallHooks_PreservesUserHooks` — Prevents data loss during uninstall
- `TestUninstallHooks_PreservesUserDenyRules` — Prevents data loss of security rules
- `TestUninstallHooks_PreservesUnknownHookTypes` — Forward-compatibility during uninstall

**Important functional tests:**
- `TestInstallHooks_FreshInstall` — Validates all 7 hooks with correct commands
- `TestInstallHooks_Idempotent` — Prevents hook duplication on re-enable
- `TestInstallHooks_LocalDev` — Validates dev-mode command format
- `TestInstallHooks_Force` — Tests force-reinstall path
- `TestUninstallHooks` / `TestUninstallHooks_RemovesDenyRule` — Clean uninstall paths

**Verdict:** No changes needed. Excellent coverage of critical data-preservation behavior.

### 5. `setup_factoryai_hooks_test.go` (integration) — Useful smoke tests

Both tests exercise the full CLI command path (`entire enable --agent factoryai-droid`). Useful for catching integration issues that unit tests miss.

---

## Key Gaps (Missing Tests)

### Not tested at all:
1. **`ExtractPrompts()`** — Parses user content from transcript and strips IDE context tags. Non-trivial logic, completely untested.
2. **`ExtractSummary()`** — Finds last assistant text message. Completely untested.
3. **Subagent token aggregation with actual files** — `TestCalculateTotalTokenUsageFromTranscript_PerCheckpoint` passes `""` for subagentsDir every time. No test validates that subagent tokens are correctly summed from real files.
4. **Malformed JSONL line handling** — The parser silently skips bad lines, but this isn't tested (what happens with `{"broken json` mid-transcript?).
5. **`HookNames()` / `GetHookNames()`** — Returns the list of 9 hook verbs. If a hook is accidentally removed from this list, no test catches it.

### Remove (trivial, zero risk of regression):
- `TestName`, `TestType`, `TestDescription`
- `TestGetHookConfigPath`, `TestSupportsHooks`
- `TestGetSessionID`

2. **`TestExtractSummary`** — Test last-assistant-message extraction
3. **`TestCalculateTotalTokenUsageFromTranscript_WithSubagentFiles`** — Create actual subagent JSONL files and verify tokens are aggregated
4. **`TestParseDroidTranscript_MalformedLines`** — Verify that a transcript with some broken JSON lines still parses the valid lines correctly
5. **`TestGetHookNames`** — Validate the hook list contains all expected 9 verbs (protects against accidental removal)

### No changes needed:
- `lifecycle_test.go` — All useful
- `hooks_test.go` — All useful
- `transcript_test.go` — All useful (except note the gaps above)
- Integration test — Useful as-is
