  3. Important Discoveries

  1. Pre-existing merge bug. mergeJSON only patches a specific allow-list of fields. Review is
   decoded into a temp struct for validation but never copied to the merged result. Any
  current user with review: in settings.local.json has it silently ignored. This must be fixed
   alongside any destination change or the picker writes won't take effect when a base
  settings.json exists.
  2. Worktree-share constraint. User pushed back on .entire/settings.local.json because it's
  per-worktree and "most people work in worktrees." Discovered that shared-across-worktrees +
  not-committed is only achievable via .git/ (the common dir, shared across worktrees by git
  worktree semantics) or outside the repo entirely. There is no third location.
  3. Existing precedents in the codebase:
    - .git/entire-sessions/ is already used for shared-across-worktrees session state
  (CLAUDE.md confirms).
    - ~/.config/entire/ already exists and contains version_check.json (managed by
  cmd/entire/cli/versioncheck/versioncheck.go:100) — but used only as a cache today, not user
  preferences. Establishing user preferences there would be a new pattern within this
  codebase.
    - The codebase reads from git config (e.g., getGitConfigValue at
  cmd/entire/cli/git_operations.go:93 for user.signingkey, etc.) but never writes its own
  keys. Integration test guard at cmd/entire/cli/integration_test/testenv.go:266 fails tests
  if .git/config mutates unexpectedly.
  4. Self-quieting nudge mechanics: Detection uses LoadFromFile(EntireSettingsFile)
  (project-only, no merge) and checks len(s.Review) > 0 || s.ReviewFixAgent != "". After
  migration, s.Review = nil + json:"review,omitempty" makes the key disappear from the file →
  nudge stops firing automatically.
  5. Migration ordering matters: Must write user-prefs file FIRST, THEN strip project. If
  reversed, a mid-flight crash loses data. If correctly ordered, a mid-flight crash just
  leaves both files populated → wholesale-replace merge means the user-prefs side wins → user
  is fine, nudge re-fires next run, user retries --edit.
