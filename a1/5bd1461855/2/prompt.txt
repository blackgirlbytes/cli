1. `--yes` still fails in non-interactive agent-management flows on already-configured repos. In [cmd/entire/cli/setup.go](/Users/soph/Work/entire/devenv/cli/cmd/entire/cli/setup.go:320), `runManageAgents` returns early when `interactive.CanPromptInteractively()` is false, before it ever consults the injected `selectFn`. That means `entire configure --yes` / `entire enable --yes` cannot actually “skip prompts” in CI or other non-TTY contexts once the repo is already set up; it just prints “Cannot show agent selection in non-interactive mode.” The new tests only cover `detectOrSelectAgent`, not this path.

2. `--yes` overrides explicit telemetry opt-out and the env opt-out. In [cmd/entire/cli/setup.go](/Users/soph/Work/entire/devenv/cli/cmd/entire/cli/setup.go:907), `opts.Yes` unconditionally sets `settings.Telemetry = true`, bypassing the existing precedence rules in [promptTelemetryConsent](/Users/soph/Work/entire/devenv/cli/cmd/entire/cli/setup.go:1628). As written, `entire configure --yes --telemetry=false` still enables telemetry, and `ENTIRE_TELEMETRY_OPTOUT=1 entire configure --yes` also enables telemetry. That contradicts both the flag semantics and the prior env-based opt-out behavior.
