1. High: resume can no longer use checkpoint_remote from forked clones or any repo whose origin owner differs from the checkpoint repo owner. cmd/entire/cli/strategy/
     checkpoint_remote.go:288 resolves the URL by calling resolvePushSettings(ctx, "origin"), and that path applies the push-only fork check in cmd/entire/cli/strategy/
     checkpoint_remote.go:95. As a result, cmd/entire/cli/git_operations.go:460 and cmd/entire/cli/resume.go:626 will behave as if no checkpoint_remote is configured,
     even though reading checkpoints from that repo is exactly what resume should do. This is a correctness regression for the fork workflow the feature is trying to
     support.
  2. Medium: ResolveCheckpointRemoteURL is no longer a pure “resolve” helper; it can perform a fetch and mutate local refs as a side effect. The call at cmd/entire/cli/
     resume.go:626 is only checking whether a checkpoint remote exists, but under the hood cmd/entire/cli/strategy/checkpoint_remote.go:288 goes through
     resolvePushSettings, which may call fetchMetadataBranchIfMissing at cmd/entire/cli/strategy/checkpoint_remote.go:116. Then the code immediately does the explicit
     fetch again at cmd/entire/cli/resume.go:630. In the “branch missing locally” case this guarantees two network fetches, and the first one is hidden behind what looks
     like a cheap config probe.
