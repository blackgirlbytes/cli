Follow up to reading: https://techstackups.com/guides/entire-io-hands-on-what-it-actually-captures/#what-leaks-into-checkpoints

The article points out that shadow branch commits can contain files that should be gitignored. The current implementation had a gap that if the agent touched a gitignored file in a session the file would show up in `ModifiedFiles` / `NewFiles` and the shadow branch logic would then add that file to the shadow branch. Shadow branches are branches that should stay local and are temporary to track changes the agent makes. While entire will never push those branches to a remote there is a risk this happens accidentally so make sure we don't track anything that is gitignored there since we won't need it anyway. 

This fixes it properly to always check if files are covered by gitignore and will not add them.
