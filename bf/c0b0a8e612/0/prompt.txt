# Fix: Droid Token Usage Offset Mismatch

## Context

`calculateTokenUsage` in `manual_commit_condensation.go` has a bug for Droid transcripts. The `startOffset` parameter is a raw JSONL line count (from `countTranscriptItems`), but it's used as an index into the array returned by `ParseDroidTranscriptFromBytes`, which filters out non-message entries (`session_start`, `session_event`, etc.). This causes incorrect token counting — either under-counting (off by N non-message entries) or over-counting all tokens when the offset exceeds the filtered array length.

The file-based `ParseDroidTranscript(path, startLine)` already handles this correctly by applying the offset at the raw line level before filtering. The byte-based `ParseDroidTranscriptFromBytes` does not accept an offset parameter.

## Approach: Add `startLine` parameter to `ParseDroidTranscriptFromBytes`

This mirrors the existing `ParseDroidTranscript(path, startLine)` API. All existing callers pass `0` (no behavioral change), and the bug site passes `startOffset`.

Option B (changing `countTranscriptItems` to count only messages for Droid) was rejected because it would break `transcript.SliceFromLine` scoping (line 230) and `sessionHasNewContent` comparisons (line 1036), which both depend on raw line counts.

## Steps

### 1. Modify `ParseDroidTranscriptFromBytes` signature

**File:** `cmd/entire/cli/agent/factoryaidroid/transcript.go`

Change:
```go
func ParseDroidTranscriptFromBytes(content []byte) ([]transcript.Line, error) {
    lines, _, err := parseDroidTranscriptFromReader(bytes.NewReader(content), 0)
    return lines, err
}
```
To:
```go
func ParseDroidTranscriptFromBytes(content []byte, startLine int) ([]transcript.Line, error) {
    lines, _, err := parseDroidTranscriptFromReader(bytes.NewReader(content), startLine)
    return lines, err
}
```
