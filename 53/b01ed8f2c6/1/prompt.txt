ok, one more thing on top, can you take a look with 0.129.0 we are getting this when starting codex:

## Track Codex `apply_patch` mid-turn + serialize all session-state writes

When Codex commits mid-turn (which it routinely does), the previous strategy had no per-tool file accounting — `state.FilesTouched` stayed empty until the Stop hook, so PostCommit's carry-forward decision fell back to whole-transcript extraction, over-reported "remaining" files, and reset `CheckpointTranscriptStart` to 0 on the next checkpoint. Two same-session checkpoints both showed `start=0` even though the transcript was cumulative.

### What this PR does

**Wires Codex's PostToolUse hook through to `state.FilesTouched`.** Codex (post-#18391) emits PostToolUse for every `apply_patch` with the patch envelope in `tool_input.command`. We now install a fourth hook command, parse the envelope (Add/Update/Delete plus `*** Move to:` renames), and merge paths via a new `agent.ToolUse` lifecycle event — so PostCommit sees an accurate file list and the carry-forward logic stops firing spuriously.

**Funnels every session-state mutation through `MutateSessionState`.** PostToolUse fires at high frequency and Codex parallelizes tool calls. To eliminate lost-update races against TurnEnd / PostCommit / condense / model update / review-env / SessionEnd / etc., every load-modify-save in the lifecycle dispatcher and strategy package now goes through one helper that takes an OS flock against `.git/entire-session-locks/<id>.lock` for the load+fn+save. A per-process gate keyed by goroutine ID layers on top so nested calls in the same goroutine share the outer's state pointer rather than deadlocking on a second flock or losing inner updates to the outer save.

### Notable bits
- Lock files live in a sibling dir (`entire-session-locks/`) so session listings don't see them, and `ClearSessionState` deliberately doesn't unlink them (flock + unlink + recreate would lose mutual exclusion).
- `initializeSession` re-checks under the lock to avoid a TOCTOU that would overwrite a richer concurrent state with blanks.
- `SessionMetadata.CheckpointTranscriptStart` exposed in e2e testutil for future agent-validation tests.

### Tests
- Codex parser: apply_patch + Write/Edit aliases, non-mutating tools, empty patch, missing tool_input, Move-to renames, mixed siblings.
- Strategy: parallel `RecordFilesTouched` merges across 20 goroutines; nested `MutateSessionState` calls reentrant in the same goroutine; `ClearSessionState` preserves the lock file; `MutateSessionState` doesn't clobber a richer state under a TOCTOU race.
- Integration: `entire hooks codex post-tool-use` populates `state.FilesTouched` end-to-end; non-mutating tools are no-ops.
