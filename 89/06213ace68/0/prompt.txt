fix those and what about these   Issues

  1. matchedSignal type is referenced but never defined (line 183, 215, 229). The sketch uses matchedSignal with fields
  AllowsSingleton, Count, Kind, and method AffectedSessionSet(), but there's no definition. Should add it to the sketch — it's
  load-bearing for understanding how the two layers interact.

  2. Missing GenerationStats update for the new filter. The existing filters increment stats.FilteredWeakCount or
  stats.FilteredGenericCount. The doc says the evidence gate should increment FilteredWeakCount (line 165 in the key files section
  references "replaces the call site"), but a new counter like FilteredNoEvidenceCount would be more useful for debugging — you'd
  want to know how many records died specifically because of the new gate vs. the existing weak/generic filters.

  3. The findSignal lookup strategy needs specifying. Line 216 does normalizeGeneratedText(signal.Key) then passes it to findSignal.
  But what kind of match? Exact normalized string match? Contains? The doc should state this — it matters for the false-negative
  rate. The LLM might rephrase the key slightly ("run mise run fmt" vs. "always run mise run fmt before committing"). Exact match is
  safer (fewer false positives) but will reject valid records where the LLM paraphrased. A reasonable middle ground: normalized exact
   match with a fallback to normalized-contains if the key is a substring of the signal value (or vice versa), but that should be
  called out.
