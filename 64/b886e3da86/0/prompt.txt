## Error Handling Review — PR #990 (`runExplainAuto` in `cmd/entire/cli/explain.go`)

### CRITICAL

**1. Substring matching on `err.Error()` is a silent-routing hazard** — `cmd/entire/cli/explain.go:242-245`
The codebase already exports `checkpoint.ErrCheckpointNotFound` (see `cmd/entire/cli/checkpoint/checkpoint.go:26`) and consumers use `errors.Is` (e.g., `cmd/entire/cli/resume.go:925`, `cmd/entire/cli/checkpoint/committed_reader_resolve.go:46`). `runExplainCheckpoint` however returns `fmt.Errorf("checkpoint not found: %s", …)` as a plain string (`explain.go:350`), losing the sentinel, so `runExplainAuto` can only grep. That's a genuine silent-failure risk:

- `explain.go:365` returns `fmt.Errorf("failed to read checkpoint: %w", err)`. If `err` itself wraps `ErrCheckpointNotFound` (very plausible — `committed_reader_resolve.go` returns that sentinel, and `readLatestSessionContentForExplain` at `explain.go:488` and `readV2ContentFromMain` at `explain.go:517` explicitly return it), the wrapped string contains `"checkpoint not found"` and the fallback fires. That's actually the intent — but it relies on text, not types.
- The inverse risk is real: `explain.go:379` and `:384` return `fmt.Errorf("failed to read checkpoint content: %w", err)`. If a future contributor phrases a transient read failure as "blob not found for checkpoint not found in pack" (or an IO error bubbles up any wrapped `ErrCheckpointNotFound` from a sub-reader), we silently reroute a real read failure into a commit lookup and the user gets `no checkpoint or commit found matching %q` — hiding the real IO/corruption error.
- The ambiguous-prefix error (`explain.go:359`) happens to not contain "checkpoint not found" today, but it's one word-change away from matching.

**Recommendation:** Convert `runExplainCheckpoint`'s not-found returns to wrap `checkpoint.ErrCheckpointNotFound` (`fmt.Errorf("checkpoint not found: %s: %w", prefix, checkpoint.ErrCheckpointNotFound)`), then in `runExplainAuto` use `errors.Is(checkpointErr, checkpoint.ErrCheckpointNotFound)`. Introduce a new sentinel (e.g. `ErrCannotGenerateTemporary`) for the generate-on-temporary case at `:339`. This matches the established pattern in `resume.go:925`.
