PR #877 Review Summary

  Checkpoints V2: Support checkpoint_transcript_start for compact transcript.jsonl files

  11 files changed, +520/-97

  ---
  Critical Issues (2 found)

  1. Accumulation pattern (+=) is fragile and non-self-correcting

  [silent-failure-hunter] manual_commit_condensation.go:268-271, condensation.go:1028, condensation.go:1137, hooks.go:1317

  CheckpointTranscriptStart uses absolute assignment (=), making it self-correcting. CompactTranscriptStart uses relative accumulation (+=), meaning any
  single failure in the chain permanently corrupts all subsequent checkpoints in the session. This is the root architectural concern:

  state.CheckpointTranscriptStart = result.TotalTranscriptLines   // self-correcting
  state.CompactTranscriptStart += result.CompactTranscriptLines    // fragile accumulator

  If CompactTranscriptLines is ever 0 due to a silent failure (redaction error, partial compact success), the offset stops advancing and never recovers.

  Additionally, compactLines at line 268-271 has no negative guard:
  compactLines = fullLines - writeOpts.CompactTranscriptStart
  If CompactTranscriptStart somehow exceeds fullLines, this goes negative and CompactTranscriptStart would decrease.

  Recommendation: At minimum, add max(0, ...) guard and a warning log. Ideally, consider whether this can be made self-correcting like the full-transcript
  counterpart.

  2. Redaction failure permanently poisons the session's compact offset chain

  [silent-failure-hunter] manual_commit_condensation.go:326-358

  When redact.JSONLBytes fails, redacted is set to nil, both compactTranscriptForV2 calls return nil, and CompactTranscriptLines becomes 0. The
  accumulation state.CompactTranscriptStart += 0 means the offset stops advancing -- not just for this checkpoint, but for every subsequent checkpoint in
  the session. The current warning log says "skipping transcript.jsonl on /main" but doesn't indicate the cascading impact.

  Recommendation: Either compute what CompactTranscriptLines would have been from un-redacted data, or log at ERROR level that the session's compact offset
   tracking is now broken.

  Important Issues (4 found)

  3. computeCompactOffset in migrate.go has zero logging on failure paths

  [silent-failure-hunter] migrate.go:454-476

  Returns 0 on 5 distinct failure paths (empty transcript, missing agent, compaction error, negative offset) with no logging at all. During migration, this
   silently bakes incorrect offsets into permanent storage. Its sibling computeCompactTranscriptStart in condensation.go does log on some failures -- this
  function should too.

  Recommendation: Add logging.Warn calls (requires adding ctx parameter). At minimum, log compaction errors and negative offsets.

  4. Partial compact success produces inconsistent state

  [silent-failure-hunter] manual_commit_condensation.go:347-354

  Two independent compactTranscriptForV2 calls (scoped and full) could have one succeed and one fail. If full succeeds but scoped fails,
  CompactTranscriptStart = 0 and CompactTranscriptLines = entire cumulative count, inflating the next checkpoint's offset.

  Recommendation: If either compact call returns nil, treat both as nil.

  5. No unit tests for computeCompactTranscriptStart or computeCompactOffset

  [test-analyzer]

  These are the core offset computation functions with 4-5 distinct code paths each. They're only tested indirectly through integration tests. The legacy
  fallback path (where state.CompactTranscriptStart == 0 but state.CheckpointTranscriptStart > 0) has no test coverage. The migration test also uses
  computeCompactOffset to compute its own expected value (tautological pattern).

  Recommendation: Add direct unit tests covering edge cases: empty transcript, missing agent, negative offset, legacy session recalculation.

  6. Repair path in migrate.go doesn't set CompactTranscriptStart

  [silent-failure-hunter] migrate.go:250-269

  repairPartialV2Checkpoint uses UpdateCommittedOptions which has no CompactTranscriptStart field. Repaired checkpoints may have compact transcripts but no
   corresponding offset metadata.

  Recommendation: Verify whether UpdateCommitted preserves existing metadata or if the repair path needs the compact offset.
